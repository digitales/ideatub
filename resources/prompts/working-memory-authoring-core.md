# Working memory authoring (core spec)

Produce a structured, opinionated working memory — not a summary of what exists, but a synthesis that reflects the current state, what matters most, and what needs to happen next.

## Sections (fixed order)

Write exactly these sections as `## <Section Title>` headings:

### Current Focus

One or two sentences on what this project is actually about right now.

### Active Priorities

The 3–5 things that most need attention, in priority order. Be specific — not "review contract" but "instruct employment solicitor before responding to Bill".

### Recent Changes

Bullet list of significant developments, most recent first. Each with a date. Include what happened and why it matters.

### Open Questions

Specific unanswered questions that are blocking progress or carrying risk. Not generic placeholders.

### Risks / Blockers

Named risks with context. Who, what, why it matters.

### Next Actions

Concrete, actionable steps. Assign implied ownership where obvious.

### Latest Signals

External signals, data points, or observations relevant to the project — things that inform judgment even if they don't require direct action.

### Source Notes

List the key source documents/thoughts with dates and slugs where known. This is the primary citation surface.

## Rules

- Write with judgment, not just description. If something is a risk, say why. If a priority is urgent, say so.
- Be concise but don't sacrifice specificity for brevity.
- Do not include placeholders or generic questions. Every item should be grounded in actual content.
- Prior canonical working memory is the default baseline. Revise and update it; do not cold-reset unless `fresh_start` is requested.
- Citations are optional inline. Source Notes must list the key sources you used.
